# LifeAtlas

## 项目简介

LifeAtlas 是一款围绕个人生活记录、穿搭管理和 AI 辅助分析设计的生活管理 App。

本文件只记录项目整体情况。详细产品需求统一维护在 `REQUIREMENTS.md` 中。

## 当前版本

- 版本号：`2.5.5`
- 构建号：`43`
- 当前阶段：穿搭板块完整品类参数、Doubao 图片识别、预购文字分析、Cloudflare Workers HTTPS 代理及单账号短期令牌认证已接入；真实天气及今明逐小时预报已接入；其他 AI 功能及系统后台唤醒待后续接入

## 项目目标

- 建立统一的个人生活记录入口，关联天气、日历、文字、图片和每日穿搭。
- 管理衣物、套装、穿搭记录、预购衣物和个人身材数据。
- 基于天气、历史穿着数据和用户身材提供 AI 辅助分析与穿搭建议。
- 支持用户按需开启或关闭功能板块，并在关闭时保留已有数据。
- 保持清晰的需求、版本和开发规则记录。
- 以小范围、可验证、可回溯的方式持续迭代。

## 护肤模块（2.0.0）

从我的－板块管理启用。建立档案和目标，搜索或拍摄产品并确认资料版本，生成规则/AI计划，预览确认后逐步执行。SQLite v12 保留旧数据，历史步骤保存快照。产品库为独立 JSON 版本包，目前精选 4 款美国官网资料，未收录产品可先记录名称。

护肤 AI 需部署 `tooling/cloudflare_worker` 新增接口，复用既有安全登录；没有部署时可使用本地规则方案。客户端不包含供应商密钥。Android 提醒为非精确定时，未来 28 天滚动安排，每次进入/恢复更新；iOS 通知尚未实现。

条码补充查询采用 Open Beauty Facts 公共接口，由用户主动触发，仅发送条码；社区数据保留来源及 ODbL 标识，不视为已核实产品资料。

## 2.3.1 天气调整

天气与城市页保留简洁官网归因，底部左侧获取时间、右侧独立刷新；下方显示按城市时区分组的今天/明天小时预报。首页不显示获取时间。代理扩展为 `weatherHourly`，通过和风 `/weather/v1/hourly/{latitude}/{longitude}?hours=72` 获取数据；需配套后台版本，未开通小时服务时明确提示错误，保留当前天气。城市缓存15分钟，手动刷新绕过缓存。


## 菜谱与购物清单导出（2.3.5）

菜谱详情右上角点击导出图标，预览完整菜谱图片并通过系统分享面板导出。主图可用时包含主图；长内容自动分页成多张PNG，可左右滑动和缩放查看。购物清单右上角可选导出图片或文字，保留当前菜谱份数、合并用量、已准备状态和未定用量提示；文字可直接复制或分享。图片的保存目的地取决于系统已安装的分享应用，不直接申请相册权限。生成内容在本机完成，不上传原资料。


## 我的身材第一期（2.4.0）

首次进入在独立设置页填写8至128位密码和确认密码。记录日期与已知身体尺寸，空项可不填；新增沿用最近档案并标记，历史可修正或删除，字段右侧提供测量帮助。2.5.2移除尺码偏好分组与恢复码交互，旧加密格式在原密码验证成功后迁移，历史字段保留在密文中。档案仍通过AES-GCM本机加密、PBKDF2派生密码密钥，离开App锁定并关闭敏感子页面。手机号找回暂未开放，仅预留接口，详见 BODY_PASSWORD_RESET.md。衣柜对比展示同单位尺寸及差值，暂不包含AI、趋势曲线或生物识别。

## 全局知识搜索（2.5.0）

首页搜索入口统一检索菜谱、库存、衣物/套装/预购、护肤产品/计划/执行记录和日历文字。输入时展示匹配问题，固定说明使用版本化知识库，购物清单、天气和护肤步骤使用当前数据模板。答案包含来源，可跳转原内容及分页导出图片。

搜索索引仅保存在会话内存，不改变原数据表。身材数值不进入全局索引；离开应用清除查询与私人答案。关闭板块仍可检索保留记录，打开原内容前明确选择启用。没有资料时说明缺失，不调用通用大模型补写答案。细节见 `GLOBAL_SEARCH_DESIGN.md`。

## 尺寸识别诊断（2.5.3）

连接中断、安全连接失败、超时和无效响应分别提示；失败后点击“查看错误详情”可复制安全诊断。完整请求使用同一总时限，失败不自动重复调用模型。详情只包含类别、阶段、耗时及可用的 HTTP/追踪信息，不包含图片或认证凭据。实际手机故障仍需依据下一次请求的诊断定位，见 `AI_RECOGNITION_DIAGNOSTICS.md`。

## 穿搭记录与温度纠错（2.5.4）

记录模式可选择过去日期补记，默认今天；换日不会静默带入另一日的选择。裤装臀围、大腿围改为范围，详情统一“尺寸”。应用首页衣服仅展示名称，穿搭三列卡片信息保留。

SQLite v14 记录天气城市、时区、来源与确认状态，衣服温度由已确认的每日穿搭重算。旧版温度缺少来源，保留并标记待确认，不再参与推荐统计；选择对应日期的“旧温度待确认”，核对/修正后保存即可恢复该日统计。不会把真实的 30℃ 批量改掉。

AI 客户端兼容旧单值、旧范围文本及新上下限字段；服务端范围提示词及白名单更新位于 `tooling/cloudflare_worker/worker.js`，独立 Worker 部署需单独核验，APK 发布本身不会部署此 Worker。

## 衣柜展示与今日温度同步（2.5.5）

衣柜单件和套装内衣服只保留图片与名称；详情、预购详情和筛选以绿色/蓝色/紫色区分季节、种类和品牌。围度单值、单边或相等上下限显示一个数值，不修改原始边界；裤长名称改为单行 `裤长(外长)`，窄屏大字时数值可另起一行。

主动保存今日穿搭后，同步当前城市当日真实天气（包括有效缓存），并重新读取最新衣物温度。今日旧待确认记录可通过这次主动记录确认；过去未确认记录仍保留原值等待核对。手动温度和其他城市的已确认记录继续受保护，无可用天气时明确提示未更新。数据库仍为 v14，无新增迁移。
